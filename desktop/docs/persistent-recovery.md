# 2026-11-26：持续恢复与沿墙失跟踪

依据 11 月 23 日采集记录，5 秒永久超时会让短暂失败变成长时间停止更新。
用户明确要求修改算法本体、覆盖桌面副本并同步 GitHub；本次属于算法维护，
不是对首次导入 vendor 文件的原样保留。首次导入的历史哈希仍用于追溯。

## 行为

- 默认 `max_tracking_gap` 从 5 秒改为 30 秒，语义改为进入低频恢复的时间点，
  不再是永久放弃恢复的期限。超时不自动重置坐标原点，也不把独立地图硬接起来。
- 失跟踪超过 5 秒后，没有候选时最多每 0.5 秒搜索一次；超过 30 秒后，
  默认每 1 秒搜索一次。候选出现后仍连续处理确认帧，不受限频阻碍。
- 恢复搜索半径最多 3 米（受速度上限约束），配合更密的平移候选。
  多个空间分离、置信度相近的搜索结果被拒绝为 `LOST: ambiguous recovery`。
  这是有界局部恢复，不是全局重定位，也不能保证辨认重复结构。
- 保留 60 点、几何退化、残差、运动上限及连续 3 帧确认规则。
  只看到平行墙时，沿墙位移不可观测；不会把冻结位姿当作静止测量。
- 在线 `poseValid` 仅对本帧已接受位姿为 true。初始化、恢复、失踪与退化
  均为 false；地图显示英文提示：当前位姿未知，标记是最后可信位置，船可能仍在移动。
- 诊断增加 `pose_valid`、`motion_observable` 和 `recovery_mode`。
  这些是当前完整位姿是否可信的布尔标记，不是逐轴协方差，也不表示已实现 IMU 融合。

## 取舍与验证

扩大搜索可找回原先 0.8 米门限之外的运动，但仍会在超过局部搜索范围、墙面方向
不足或场景重复时拒绝定位；纯二维雷达不能凭空补出沿无限长墙的运动。
不通过降低几何检查门槛制造连续轨迹，不把合成测试当作水上定位精度证明。

原有三个“必须在 5 秒/指定截止时刻永久失败”的测试按新需求改为验证：
延长窗口、不发布未确认位姿、长时间后仍需 3 帧确认才能恢复。其他断言不放宽。
新增测试覆盖 1.2 米位移恢复、12/40 秒失跟踪恢复、平行墙不可观测及无效参数。

相关配置在 `desktop/algo/cocommand2d/slam/core.py` 的 `SlamConfig`。
桌面运行程序必须重新启动 Python 侧车后才会加载覆盖后的代码。

  本数据没有外部位姿真值：接受帧数增加不等于定位精度提升，也不证明所有重定位正确。
